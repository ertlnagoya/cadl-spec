1. はじめに

1.1 本文書の目的と範囲​

CADL（Contract Architecture Description Language）は，System of Systems（SoS）における制度設計を形式的に記述・検証・配備するためのドメイン固有言語（DSL）である。本文書は，CADLの言語仕様（Version 0.2，ドラフト）として，言語の目的，要求仕様，構文・意味論の定義，処理系の設計方針を示す。

本文書は，ERTLにおけるSoS研究の調査およびSoSアーキテクチャ設計論の検討に基づき，CADLの実装に向けた仕様を整理したものである。

第1章と第2章は言語の目標を述べるものである。リファレンス実装が現時点で提供する範囲は，第10章と付録AのA.12節に示す。

1.2 背景: SoSにおける制度設計の課題​

SoSは，独立に運用される複数のシステムが相互に連携し，単独のシステムでは実現できない能力を発現するシステム構成である [Maier, 1998]。[ISO/IEC/IEEE 21841:2019] では，SoSをDirected（統率型），Acknowledged（認知型），Collaborative（協調型），Virtual（仮想型）の4種に分類している。

従来のSoS研究は制御・協調アルゴリズムや技術的最適化に焦点を当ててきたが，ガバナンス・制度設計がシステム全体の振る舞いを構造的に規定する上位層の設計変数として注目されている。しかし，現在のSoS制度設計は自然言語の契約・合意書に依存しており，以下の課題が存在する。

  • 曖昧性・矛盾の検出が困難: 自然言語による制度記述では，形式的な無矛盾性検証ができない。
  • 制度更新の整合性保証の欠如: 構成システムの追加・離脱に伴う制度更新が手動であり，整合性チェックの工学的手段がない。
  • 設計と実装の乖離: 制度の設計意図が実装に正確に反映されているかの検証手段がない。
  • 制度のパラメータ化の不在: ガバナンス構造を定量的に操作可能な変数として扱うフレームワークが存在しない。
  • 3層統合記述の欠如: 制度（権限構造），プロトコル（協調手順），アルゴリズム（計算手法）を統一的に記述できる言語がない。
  • 専門家以外の関与困難: 既存の形式手法やアーキテクチャ記述言語は高度な専門知識を前提としており，学生・企業の実務者・自治体職員・市民が制度設計に主体的に参加することが困難である。

上記の課題に加え，CADLの設計動機として，SoS制度設計を「計算の対象」として扱うことへの根本的な要請がある。以下の3つの目的が，CADLという言語を新たに設計する直接的な動機となっている。

目的1: SoS制度設計を計算機で扱えるようにする​

現実世界のSoSでは，制度の多くが人間の暗黙知・慣習・経験則として存在しており，明文化すらされていない場合が多い。例えば，家庭内の家事分担のルール，地域コミュニティの暗黙の合意，組織間の非公式な協力関係などは，関係者の頭の中にのみ存在し，外部から観察・分析することが極めて困難である。

CADLは，こうした暗黙のルールや習慣を含む現実のSoS制度を「モデル化・言語化」し，計算機上のオブジェクトとして操作可能にすることを第一の目的とする。制度が計算機上のデータとして存在することで，以下の操作が可能になる。

  • コピー・再利用: ある文脈で有効だった制度設計を別の文脈にコピーし，適応させることができる。例えば，ある家庭の家事分担ルールを別の家庭に移植し，家族構成に合わせて調整する。
  • 統合・合成: 複数の部分的な制度記述を統合して，より大きなSoSの制度を構成できる。例えば，配送ロボットの経路制度とデータ共有の制度を統合して，配送データ連携制度を構成する。
  • バージョン管理・差分比較: 制度の変更履歴を追跡し，任意の時点の制度に戻すことができる。制度の変更箇所を差分として可視化し，変更の影響範囲を特定する。
  • 検索・分類: 蓄積された制度記述のリポジトリから，類似の制度パターンを検索し，再利用候補を推薦する。
  • 暗黙知の顕在化: 人間へのインタビューやAIによる観察データの分析を通じて，暗黙のルールをCADL記述として明文化する。これにより，制度の共有・議論・改善のための共通基盤が生まれる。

目的2: SoSの制度違反や矛盾を計算できるようにする​

制度が形式的に記述されていれば，その無矛盾性の検証や，実行時の違反検出を計算によって行えるようになる。現状では，制度間の矛盾（例: ある契約では情報共有が義務付けられているが，別の契約ではプライバシー保護のため共有が禁止されている）は，人間が逐一確認するしかなく，SoSの規模が大きくなると見落としが不可避である。

CADLは，制度の矛盾検出と違反監視を計算機の力で自動化することを第二の目的とする。これは以下の2つの側面を含む。

  • AIとの融合による設計支援: LLM等のAIが，CADL記述を入力として受け取り，矛盾の検出・修正提案・制度の改善案を自動生成する。自然言語で「このルールとあのルールは矛盾していませんか？」と問いかけると，AIがCADLの形式意味論に基づいて回答する。将来的には，自然言語の要望からCADL記述を自動生成し，形式検証を経て配備するワークフローを実現する。
  • 人間の意思決定支援: 制度の矛盾や潜在的な問題を可視化し，人間の制度設計者が情報に基づいた判断を行えるようにする。矛盾の深刻度や影響範囲を定量的に提示し，修正の優先順位付けを支援する。制度変更のシミュレーション（what-if分析）により，変更の影響を事前に把握する。

目的3: SoS制度設計から制御への自動変換・最適化・コード生成​

制度設計が形式言語で記述され，検証が完了したならば，その次のステップとして，制度記述から制御ロジック・実行コードを自動生成することが自然な帰結となる。現状では，制度の設計（ポリシー文書）と実装（コード）の間に大きなギャップがあり，設計意図が実装に正しく反映されているかの保証がない。

CADLは，制度記述から実行可能な成果物への変換パイプラインを提供することを第三の目的とする。具体的には以下の変換を想定する。

  • 制度から制御ロジックへの自動変換: CADL記述の契約・プロトコル定義から，各アクターの制御ロジック（状態機械，イベントハンドラ，協調プロトコルの実装）を自動生成する。例えば，ロボット配送システムの制度記述から，DISPATCHERの割当アルゴリズムとROBOTの経路追従ロジックのスケルトンコードを生成する。
  • 制度パラメータの最適化: 制度パラメータ（α, β, λ等）の値を，シミュレーションまたは数理最適化によって自動チューニングする。環境条件の変化に対して最適な制度パラメータの組み合わせを探索し，モードマップを自動構築する。
  • ランタイムコードの生成: 契約の監視コード（assume/guaranteeの充足チェック），プロトコルの実行エンジン，メトリクス収集コードをターゲット言語（Python, TypeScript, Solidity等）で自動生成する。
  • アシュアランスケースとの連動: 制度の検証結果をアシュアランスケース（安全性論証）の証拠として自動組み込みし，IEC 62853の合意記述データベースへのエクスポートを行う。

横断的特徴: 誰でも理解できる制度記述言語​

上記3つの目的を貫く横断的な特徴として，CADLは「学生から企業の実務者，自治体職員，地域の住民まで，誰でも制度記述の意図を理解し，制度設計に参加できる」ことを重視する。SoSの制度設計は，技術者だけでなく多様なステークホルダが関与するプロセスであり，制度を記述する言語がごく一部の専門家にしか読めないのであれば，制度設計の民主化は実現しない。

この万人理解性を実現するため，CADLは以下のアプローチを採る。

  • YAMLベースの宣言的構文: プログラミング経験がなくても構造を直感的に把握できるインデントベースの記述を採用する。JSON/XMLに比べて「読める」構文を優先する。
  • 自然言語に近い語彙: authority（権限），responsibility（責任），incentive（インセンティブ）など，制度の概念をそのまま反映した語彙を用いる。専門的な形式手法の記法を極力隠蔽する。
  • 段階的記述レベル: (1) 概要レベル（自然言語に近い記述，AIによる自動生成の入口），(2) 設計レベル（パラメータと制約の定義），(3) 検証レベル（形式的なassume-guarantee記述）の3段階を設け，利用者の専門性に応じた参加を可能にする。
  • ビジュアライゼーション: CADL記述からダイアグラム（権限構造図，プロトコルシーケンス図，モードマップ）を自動生成し，非技術者でも制度の全体像を視覚的に把握できるようにする。
  • AI支援による敷居の低減: LLMを介した自然言語でのCADL記述生成・修正・説明機能により，「CADLの構文を知らなくても，やりたいことを自然言語で伝えれば制度が記述される」環境を提供する。

これら3つの目的と万人理解性の横断的特徴を統合すると，CADLが目指すビジョンは「現実世界の制度を誰でも理解できる形で言語化し，計算によって検証・改善し，自動的に実行可能な形に変換する」という，制度設計のエンジニアリングサイクルの確立である。これは，ソフトウェア工学におけるモデル駆動開発（MDD）の考え方を，SoSの制度設計領域に拡張し，同時にその参加者を専門家から社会全体へ広げたものと位置づけることができる。

1.3 用語集​

本文書では多くの専門用語を使用する。基本概念，制度設計の用語，制度パラメータ（α，β，λ），制度の動態，検証・コード生成，SoS分類と関連規格の用語は，平易な説明と，必要に応じて具体例を添えて，用語集のページにまとめている。
