2. 言語の目的

2.1 CADLが解決する問題​

本章は，第1章と同じく，言語の目標を述べるものである。リファレンス実装が現時点で提供する範囲は，第10章と付録AのA.12節に示す。

CADLは，SoSにおける「制度・プロトコル・アルゴリズムの3層を単一言語で記述し，形式検証で無矛盾性・安全性を設計段階で検証する」ことを目的とする。これにより，制度に対する「記述→検証→配備→監視」のエンジニアリングサイクルの確立を目指す。

CADLが解決する具体的な問題は以下のとおりである。

制度の形式化: 自然言語の制度記述を，機械可読かつ検証可能な形式に変換する。権限構造，情報共有範囲，インセンティブ設計を定量的パラメータとして記述可能にする。

無矛盾性の自動検証: 複数の契約間の矛盾，権限の衝突，デッドロックの可能性を設計段階で自動検出する。

動的制度切替の記述: 環境条件の変化に応じた制度の動的切替（例: C-SoSからA-SoSへの遷移）を安全性保証付きで記述する。

構成的検証の支援: 構成システムの追加・離脱時に，全体の再検証ではなく差分検証で整合性を確認する。

ランタイム監視: 配備された制度の実行時監視と，契約違反の検出・対応を支援する。

2.2 設計哲学と原則​

宣言的記述: 制度の「何を」実現するかを記述し，「どのように」は処理系が決定する。制度設計者は実装詳細から解放される。

階層的構成: SoS設計の五層フレームワーク[Shimoyama & Matsubara, 2026]に対応した階層的な記述構造を採用する。五層は，(1) 目的（Policy），(2) 制度・ガバナンス（Governance），(3) 制御・協調（Control），(4) 実行・運用（Execution），(5) 環境・外乱（Environment）である。CADL自身の3層は，この分類の中に次のように位置づく。

五層フレームワークCADLでの現れ方
1. 目的（Policy）CADLの層ではない。目的から導かれる評価基準は metrics: に書く。
2. 制度・ガバナンス制度層：actors:（参加者），contracts:（権限，情報，責任，インセンティブ），および transitions:。
3. 制御・協調プロトコル層（protocols:，協調の手順）とアルゴリズム層（algorithms:。中央・ローカルのアルゴリズムを名前で指定し，内部は記述しない）。
4. 実行・運用言語の対象外。コード生成とシミュレータ設定を通じて到達する（付録D）。
5. 環境・外乱CADLの層ではない。環境についての前提は context: に書く。

パラメトリック制度設計: 情報共有度（α），意思決定の集中度（β），インセンティブ強度（λ）等の制度パラメータを数値として操作可能にする。

契約ベース構成: assume-guarantee契約に基づき，各アクターの前提条件と保証を明示し，構成的検証を可能にする。

漸進的精緻化: 抽象的な制度記述から詳細な実装仕様へ段階的に精緻化できる。初期設計段階では自然言語に近い記述を許容し，検証に必要な情報を段階的に追加する。

ドメイン非依存: 交通・エネルギー・IoT・日常生活等，特定のドメインに依存しない汎用的な記述能力を持つ。ドメイン固有の拡張はライブラリで提供する。

万人理解性（Universal Readability）: 学生・企業の実務者・自治体職員・市民など，プログラミングや形式手法の専門知識を持たないステークホルダでも，制度記述の意図と構造を理解できること。YAMLベースの宣言的構文，自然言語に近い語彙，段階的記述レベル，AI支援による敷居の低減をその手段とする。

2.3 想定する利用者と適用場面​

CADLは「万人理解性」の原則に基づき，専門家から非専門家まで幅広い利用者を想定する。以下に主要な利用者像と，それぞれの関与レベルを示す。

SoS設計者・アーキテクト: 大規模SoSの制度構造を設計・検証する専門家。検証レベルの記述を主に使用し，形式的なassume-guarantee契約を定義する。

制度設計研究者: ゲーム理論・メカニズムデザイン等の理論を実験的に検証する研究者。設計レベルのパラメトリック記述を活用し，制度パラメータ空間を探索する。

学生・教育関係者: 大学・高専の講義やゼミで，SoS・制度設計の概念を学ぶ学生および教員。概要レベルの記述から入り，段階的に設計レベルへ進む。教育用テンプレートとAI支援が学習を加速する。

企業の実務者・プロジェクトマネージャ: 複数部門・組織間の協業ルールやサプライチェーンの制度を設計する実務者。自然言語に近い概要レベルの記述を用い，AIが設計レベルへの精緻化を支援する。

自治体職員・政策立案者: 地域の公共サービス連携やスマートシティ構想における制度設計を担当する行政関係者。ビジュアライゼーションとAI支援により，技術的詳細を意識せずに制度の議論・合意形成に参加する。

市民・コミュニティ参加者: 家庭内ルール，マンション管理組合，地域コミュニティの制度をCADLで記述し，AIが支援する利用者。概要レベルの記述とAIとの対話を通じて，日常的な制度設計に参加する。

AIエージェント: LLMによる自然言語からCADL記述への自動変換，およびCADLに基づく制度推薦を行うAIシステム。全レベルの記述を生成・処理する。

以下に，利用者ごとの主な記述レベルと支援手段の対応を示す。

利用者主な記述レベル主な支援手段
SoS設計者検証レベル（形式的記述）IDEプラグイン・型検査器
研究者設計レベル（パラメトリック）パラメータ探索ツール
学生・教員概要→設計レベル教育テンプレート・チュートリアル
企業実務者概要レベル→AI精緻化AI支援・ビジュアライザ
自治体職員概要レベルビジュアライゼーション・AI対話
市民概要レベル（AI支援）NL→CADL変換・AIアシスタント
AIエージェント全レベルAPI・パーサライブラリ
