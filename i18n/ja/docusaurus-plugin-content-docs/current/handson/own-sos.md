# コース C — 新しい SoS の end-to-end モデリング

コース C は自由度を高くしてあります。課題は概要だけを示しており、ドメインを選ぶのも、白紙から仕様を書くのも、仕様をどう動かすかを決めるのも受講者自身です。小さな自走型プロジェクトとして取り組んでください。

ロボット配送以外のドメインを選び、[テキストブック](../textbook/index.md)（第 4〜9 章）と同じ 5 段階をたどります。推奨するドメインはフードデリバリー（Collaborative SoS としてモデル化）です。さらに難しい題材に取り組むなら、大規模災害の発生直後、指揮系統がまだ成立していない段階の災害対応（Virtual SoS）を選んでください。テキストブックと違い、書き始めるための `.cadl` ファイルは提供されません。

1. アクターと契約を同定する（テンプレートはありません）。
2. SoS の類型（Maier / ISO/IEC/IEEE 21841）のどれに当たるかを判定し、宣言する `type:` の理由を説明する。
3. `lifecycle:` と `monitors:` をゼロから書き、`cadl check` を通し、cadl-explorer で確認する。
4. 自分で選んだランタイムで仕様を動かす。標準の選択肢は、IR JSON（`cadl sim-ir --format json`）からライフサイクルを再生する軽量な Python の離散事象ハーネス（例：SimPy）で、Unity は不要です。ハーネスは提供されないので、自分で書きます。
5. パラメータスイープを行い、比較レポートを書く（[テキストブック第 9 章](../textbook/09-improve.md)の演習 9.4 の 3 ページ形式がそのまま使えます）。

コース C に必要なのは公開リポジトリ（`cadl`、`cadl-explorer`）だけです。

このコースの学術的な位置付け（Maier の条件、ISO 規格、分類体系）は「[なぜ SoS-DSL なのか？](academic-background.md)」を参照してください。
