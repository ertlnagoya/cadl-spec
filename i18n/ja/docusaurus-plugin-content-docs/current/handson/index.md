# ハンズオンの案内

CADL と SoS-DSL のハンズオン教材は、目的別に 2 つのトラックに分かれています。
自分に合うトラックから始めてください。

| 読み手 | やること | 進む順 |
|---|---|---|
| 学習者 | 自分で CADL を書いて動かす | [コース A（テキストブック）](../textbook/index.md)（背景と全体構造も本文で説明しています） → B / D → C |
| 研究者 | 教材を自分の SoS の試作に流用する | [なぜ SoS-DSL なのか？](academic-background.md)を流し読み → [コース C](own-sos.md) |

:::info[リポジトリの公開状況]
`cadl-spec`（本仕様・ハンズオンサイト）、`cadl`（コンパイラ / CLI）、`cadl-explorer`（可視化）、`cadl-raspimouse-simulator`（シミュレータ）は公開しています。コース A（テキストブック）は、すべての章を公開リポジトリだけで進められます。コース D で使う `cadl-robot-town` も公開しています。コース B で使う `cadl-mobility-sos-exercise` は、現時点では公開していません。
:::

## 初めての人へ：3 段階の進め方

初めて触る場合は、理解する、雛形で練習する、ゼロから作るの 3 段階で進めてください。最初の段階ではコードを書きません。

| 段階 | 何をするか | 使う教材 | 目安 |
|---|---|---|---|
| **① 理解する** | 全体の構造（4 リポジトリ・仕様→IR→コード生成の流れ）と主要プログラムの役割を把握する | [テキストブック](../textbook/index.md)の第 1〜3 章（SoS の背景、ツールチェインと 4 つのリポジトリ、CADL 言語の要点）。背景をさらに知るには[なぜ SoS-DSL なのか？](academic-background.md) | 0.5〜1 日 |
| **② 雛形で練習する** | 用意された雛形をコピーして書き足しながら、契約の記述 → 検査 → 可視化 → シミュレーション実行をひと通り行う | [コース A（テキストブック）](../textbook/index.md) 第 1〜8 章 → 第 4〜9 章の終わりの ★・★★ 演習 | 1〜2 週間 |
| **③ ゼロから作る** | 雛形なしで機能を追加する：新しい監視・状態の追加（★★★）、別ドメインのモデリング（コース C）、LLM による契約生成ループ（発展課題） | [テキストブック](../textbook/index.md)の ★★★ 演習と第 10 章 → [コース C](own-sos.md) | 興味に応じて |

## 学習者向けの 4 コース

4 コースはどれも同じ CADL/SoS-DSL の文法を使い、扱う題材とランタイムだけが異なります。
まずコース A から始めてください。B と D はどちらも A を前提にした独立の応用コースで、片方だけでも両方でも進められます。
最後のコース C では、自分で選んだドメインを CADL で書きます。

### 始める前に：なぜ SoS-DSL なのか？

SoS とは何か、なぜ普通のプログラミング言語では書きにくいのか、CADL は何を補うのかを説明し、A〜D で前提となる用語をひと通り紹介する短い導入です。
コース A の前に読んでおくと、後の章を読み進めやすくなります。

→ [なぜ SoS-DSL なのか？](academic-background.md)

### コース A — ロボット配送（基礎）

| 項目 | 内容 |
|---|---|
| 題材 | 倉庫内のロボット配送 |
| ターゲット | Unity C# |
| 所要時間 | 約 95 分（5 分のセットアップ + 15 分 × 6 ステップ）|
| 前提 | なし。CADL に初めて触れる人向け |
| 学べること | actors / contracts / lifecycle / monitors の基本、cadl-explorer による可視化、Unity 連携 |

コース A は、ナビゲーションに独立したタブを持つ、単独で読める**テキストブック**です。第 4〜9 章の終わりに、5 回の授業の演習（全 19 課題、★〜★★★）があります。

→ [テキストブック — コース A：ロボット配送](../textbook/index.md)

### コース B — 都市モビリティ（応用）

| 項目 | 内容 |
|---|---|
| 題材 | タクシー配車の System of Systems |
| ターゲット | SUMO（交通シミュレータ）|
| 所要時間 | 60〜90 分（5 つの可視化チェックポイント付き）|
| 前提 | コース A |
| 学べること | 別ランタイムへのコード生成、契約の `guarantee` 節に対するシミュレーション結果の判定（deadline と monitor は一覧に出るが、SUMO 上では評価されない）、感度解析（CADL を書き換えて再評価する） |

→ [コース B — 都市モビリティ](mobility-sos-tutorial.md)

> コース A と同じ文法のまま、題材とコード生成のターゲットだけを差し替えます。コース A と比べて、何が同じで何が違うのかを確かめてください。

### コース D — ロボットの街（応用）

| 項目 | 内容 |
|---|---|
| 題材 | ラズパイマウスのシミュレータと同じ道路網を共有する、3 社の配送ロボット |
| ターゲット | 小さな Python のシミュレーション。規範はコース A の参照ランタイムが判定する（Unity・SUMO は不要） |
| 所要時間 | 120〜150 分 |
| 前提 | コース A |
| 学べること | システムが動いている間に、KPI に向けて規則・規制・契約を改正すること：人間が KPI を自然言語で書き、時間とともに変える。LLM が改正案を出し、自分で決めるべきでないこと（当事者の合意、顧客との約束、規制、安全、KPI どうしの衝突、確かでない改善）は、判断に必要な情報を添えて人間に判断を求める。人間の理由は自然言語と GSN で残る。改正案は検証・憲法・測った改善・投票を通る。代理指標の KPI、安全条件つきの運用モードの切替 |

→ [コース D — ロボットの街](robot-town-tutorial.md)

### コース C — 自分の SoS をモデル化（発展）

| 項目 | 内容 |
|---|---|
| 題材 | 受講者が選ぶ任意のドメイン（食事配達、緊急対応、電力グリッドなど）|
| ターゲット | 任意。標準の選択肢は SimPy のような軽量な Python の離散事象ハーネスで、Unity は不要 |
| 所要時間 | 数時間〜数週間（受講者が自分で進めるミニプロジェクト相当）|
| 前提 | コース A に加えて、コース B か D |
| 学べること | 新しいドメインに対して actors / contracts / lifecycle / monitors を自力で設計し、ランタイムも自分で選ぶ |

コース C は自由度を高くしてあり、課題は概要だけを示しています。細かい手順は書いていません。
→ [コース C — 自分の SoS](own-sos.md)

## 60 秒で動かしてみる（任意）

まず動くところをターミナルだけで見たい場合は、次を実行します。

```bash
cd ~/program/cadl_repo
./scripts/sos_dsl_handson_e2e.sh
```

[テキストブック 2.4 節](../textbook/02-toolchain-setup.md)のセットアップ（`cadl` リポジトリを `~/program/cadl_repo` としてクローン）が済んでいることが前提です。
スクリプトは同梱の `examples/sos_dsl_robot_delivery.cadl` に対して parse → IR → codegen を一気に通し、続きの案内を出します。
最後の段階では、生成した C# を `cadl-raspimouse-simulator`（`cadl_repo` の隣にある想定）の Unity プロジェクトにコピーします。まだクローンしていない場合は、代わりに `./scripts/sos_dsl_handson_e2e.sh --unity ""` を実行してください。コード生成までで終了します。
このあとは [なぜ SoS-DSL なのか？](academic-background.md)、[コース A（テキストブック）](../textbook/index.md) の順に進んでください。
