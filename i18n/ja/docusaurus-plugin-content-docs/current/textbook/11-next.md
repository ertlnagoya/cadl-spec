# 第 11 章 — 次に進む

## 11.1 何を学んだか

| 層 | 書いたもの | 書かずに済んだもの |
| --- | --- | --- |
| 仕様 | 約 110 行の CADL ファイル（第 4 章と第 5 章） | なし（仕様が唯一の出典である） |
| IR | なし | 生成された JSON（同梱の例で 297 行） |
| 可視化 | なし | Lifecycle View ページ |
| 実装 | なし | 生成された Unity C#（同梱の例で 783 行） |
| ランタイム意味論 | なし | 動く状態機械 + monitors + deadline timers |

これが SoS にとって重要なのは、ドキュメント、図、シミュレーション、コードのすべてが同じ仕様から作られるからです。仕様を変える（例えば期限を 5s から 3s にする）ときは、1 つのファイルを編集して生成コマンド（`cadl sim-ir`、`cadl codegen`、または e2e スクリプト）を再実行します。すると IR も図も生成 C# も同じ出典から作り直され、同じ規則を別の場所で手作業で書き直す必要がありません。出典が 1 つであれば、大規模な SoS の設計も保守しやすくなります。

## 11.2 次にやること

第 4〜9 章の終わりには、授業 1 回分の演習（全 19 課題、★ 〜 ★★★）があり、第 10 章には任意の発展課題が 1 つあります。演習では、本書で作ったシステムをもう一度作り、期限を縮める、モニターを増やす、ライフサイクルの状態を追加する、報酬の実行を実装する、Violation Trace View を作る、というように 1 項目ずつ変更します。5 回（または 3 回）の授業として進める方法は、[付録 C](appendix-c-teaching.md) にあります。

同じ進め方を別の問題で試すには、[ハンズオン](../handson/index.md)の他のコースに進みます。

- **[コース B — 都市モビリティ](../handson/mobility-sos-tutorial.md)**：同じ CADL の構文で、ドメインとランタイム（SUMO）を替えます。
- **[コース D — ロボットの街](../handson/robot-town-tutorial.md)**：システムが動いている間に、KPI に向けて規則・規制・契約を改正します。KPI を決め、LLM が自分で決めるべきでないことを判断するのは人間です。
- **[コース C — 自分の SoS](../handson/own-sos.md)**：概要だけを示した、自分で進める自由度の高い課題です。本書とは別のドメイン（フードデリバリー、スマート交通、組織間のデータ共有など）を選び、CADL を一から書き、自分で選んだ小さなシミュレーションハーネス（SimPy のような Python の離散事象ハーネスを勧めます）で動かし、パラメータスイープで結果を比較します。
