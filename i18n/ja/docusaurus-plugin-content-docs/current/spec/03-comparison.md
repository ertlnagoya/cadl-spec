# 3. 既存言語との比較

## 3.1 関連する言語・フレームワークの概観

**MOISE+:**
組織的マルチエージェントシステムのための構造的・機能的・義務論的記述モデル。組織の役割・グループ・ミッションを形式的に記述できるが，契約やアルゴリズムの記述は範囲外である。

**OperA:**
エージェント組織のための組織モデル。社会構造・相互作用構造・規範構造の3側面から組織を記述する。プロトコル記述に一定の対応があるが，SoSの制度層は扱わない。

**Symboleo:**
法的契約の形式仕様言語。契約の当事者・義務・権利・違反条件を厳密に記述できるが，組織構造やプロトコル，技術アーキテクチャとの統合は範囲外である。

**AADL契約拡張:** Architecture Analysis and Design Languageに契約概念を導入した拡張。assume-guarantee契約をアーキテクチャ記述に統合するが，SoSの制度層は設計対象としていない。

**SysMLv2 / HAMR:**
システムモデリング言語の次世代版とそのコード生成ツール。アーキテクチャ記述に優れるが，制度設計変数の記述は範囲外である。

**スマートコントラクト（Solidity等）:**
分散的な自己統治を実現する実装基盤。C-SoSのガバナンス実装に有望だが，制度の設計段階での検証や3層統合記述は提供しない。

**IADフレームワーク:**
Ostromの制度分析・発展フレームワーク。共有資源のガバナンスを概念的に分析するが，形式的な記述言語ではなく，定量的パラメータ化は限定的である。

## 3.3 CADLの独自性

上記の比較から明らかなように，全ての要件を単独で満たす既存アプローチは存在しない。CADLの独自性は以下の3点に集約される。

**(1) 3層統合記述:**
制度（権限・インセンティブ・情報共有），プロトコル（協調手順・タイミング制約），アルゴリズム（計算手法の抽象参照）の3層を単一言語内で一貫して記述できる唯一のDSLである。

**(2) 制度のパラメトリック設計:**
意思決定の分散度β，情報共有度α，インセンティブ強度λ等の制度設計変数を数値パラメータとして定義し，レジームマップの構築を直接支援する。

**(3) 記述→検証→配備→監視の一貫サイクル:**
設計段階の形式検証（無矛盾性・安全性），配備時のコード生成，運用時のランタイム監視を一貫した言語基盤の上で実現する。
