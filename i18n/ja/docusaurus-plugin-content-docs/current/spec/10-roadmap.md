# 10. 実装ロードマップ

CADLの実装と実用化に向けたロードマップを以下に示す。[第9章](./09-research.md)の研究方向性も考慮した計画である。期間は当初の計画であり，状況の列には公開中のリファレンス実装（`cadl` 0.3.27，2026年11月時点）が提供する範囲を記す。最新の状況は[`cadl`リポジトリ](https://github.com/ertlnagoya/cadl)のREADMEにある状況表を参照されたい。READMEの表はフェーズではなく機能を並べたものであり，2つの表の行は一対一には対応しない。

| **フェーズ**<br />（計画期間） | **目標** | **内容** | **状況** |
|---|---|---|---|
| Phase 1<br />（2026 Q2-Q3） | 言語コア設計・パーサ実装 | EBNF確定，パーサ実装，型検査器実装。MAPFシミュレータとの連携による初期評価。 | **実装済み。** パーサ，型検査器，シミュレータ向けIR・設定生成（Python，Unity，Go）を利用できる。 |
| Phase 2<br />（2026 Q3-Q4） | 検証エンジン（基本） | SMTベース無矛盾性検証，プロトコルデッドロック検出。ロボット配送シナリオでの検証実験。 | **実装済み。** Z3による無矛盾性検査とプロトコルのデッドロック検出を利用できる。検証手法`model_check`，`simulation`，`proof`は未対応である。 |
| Phase 3<br />（2027 Q1-Q2） | ランタイム・コード生成 | Python/TypeScriptランタイム生成，契約モニター実装。IoTデータ共有シナリオでの実証。 | **一部利用可能。** 契約モニタークラスを含むPythonランタイムの生成を利用できる。TypeScriptの生成は計画段階である。 |
| Phase 4<br />（2027 Q2-Q3） | AI統合 | LLMによるNL→CADL変換，モード推薦エンジン。家庭内ルール設計シナリオでの評価。 | **一部利用可能。** LLMによるNL→CADL生成（構文解析・型検査・再試行のループ付き）を利用できる。`--verify`を付けると，生成した定義に`cadl verify`のSMT検査とデッドロック検査も行う。モード推薦エンジンは計画段階である。 |
| Phase 5<br />（2027 Q3-Q4） | 制度遷移・モードマップ | 動的制度切替の安全性検証，モードマップ構築支援ツール。複数ドメインでの統合実験。 | **一部利用可能。** モード遷移のグラフ解析（到達可能性，行き止まり状態，閉路）と安全不変条件の充足可能性検査を利用できる。動的切替の安全性検証と構築支援ツールは計画段階である。 |
| Phase 6<br />（2028 Q1-） | IEC 62853連携・実用化 | アシュアランスケース連動，スマートコントラクト生成。実世界パイロットプロジェクト。 | **一部利用可能。** IEC 62853との対応付けレポートと，Solidity・OPA/Regoの生成を利用できる。アシュアランスケース連動とパイロットプロジェクトは計画段階である。 |

状況の列は処理系だけを対象とし，各フェーズに挙げた評価実験や実証は対象としない。なお，リファレンス実装は，当初の計画にないSoS-DSL拡張（[付録E](./appendix-e-sos-dsl.md)の`lifecycle:`と`monitors:`）とUnity C#の生成も提供している。

さらに5つの拡張が，[第9章](./09-research.md)の研究方向に沿って加わっている。これらも当初の計画にはない。
それぞれの付録に，リファレンス実装が提供する範囲を示している。

| **拡張** | **研究課題** | **リファレンス実装（`cadl` 0.3.27）** |
| --- | --- | --- |
| 規範（[付録F](./appendix-f-norms.md)） | RD-6.1，RD-6.2，RD-6.3，RD-6.5 | 静的な規則。記録したトレースからの判定と改正の計算（`cadl norms-eval`，`cadl norms-diff`）。生成したPythonコードでのオンライン監視（`norms_monitor.py`）。述語の中の限量子，集約，`[*]` 参照の評価。`cadl` 0.3.25から，PRISMによる1つの契約インスタンスの設計時の検査（`cadl norms-check`，F.12）と，生成したRegoとSolidityでの監視（D.5）。`cadl` 0.3.26から，正確な数と時刻と，限量子を含む述語，与えた範囲での比較と算術，複数のインスタンス，改正の設計時の検査。生成したUnity C#での監視と，RegoとSolidityが拒否するもの（限量子，集約，ワイルドカード参照，改正）の監視は提供しない。 |
| エージェント統治（[付録G](./appendix-g-agents.md)） | RD-8.1，RD-8.2，RD-8.3 | 静的な規則。1つのメッセージに対する決定関数（`cadl agents-decide`）。RegoとCedarの境界方針。記録したトレースを再生し，保留，委任，監査記録を扱うリファレンスランタイム（`cadl agents-run`）とそのオンラインでの利用。改ざんを検出できる監査記録（`cadl audit-verify`）。Model Context Protocolのゲートウェイ（`cadl mcp-gateway`）。`cadl` 0.3.25から，JSON-RPCによるA2A 1.0.0のゲートウェイ（`cadl a2a-gateway`）。`cadl` 0.3.26から，A2Aのストリーム，署名した保留，公式のMCPとA2AのSDKによる試験。stdio以外のMCPのトランスポートと，A2Aのプッシュ通知とほかのバインディングは提供しない。 |
| 確率モデル（[付録H](./appendix-h-stochastic.md)） | RD-1.3 | 静的な規則。PRISM言語への書き出し（`cadl model-export`）。パラメータの値を固定した参照評価器（`cadl model-check`）。パラメータリフティングによる認証付きのモードマップ（`--certify`）。契約からのモデルの導出は提供しない。 |
| 戦略モデル（[付録I](./appendix-i-games.md)） | RD-7.1，RD-7.2 | `cadl` 0.3.23から。静的な規則。記憶なしで決定的な名前付きのプロファイルが単独の逸脱に対して均衡であるかの検査と逸脱利得，認証付きの均衡マップ（`cadl game-check`）。PRISM-gamesへの書き出し。0.3.24からは，任意の戦略モデルでの両端による認証と，概念 `every_reachable_state`。0.3.26の次のバージョンでは，I.9の条件PD+とPD−（1ステップの優位による）と，PRISM-games 3.2.4との書き出しの比較。`cadl` 0.3.27から，PRISM-games 3.2.4で確かめた書き出しと，性能差による条件PD+とPD−も使うマップの判定（I.9）。部分観測のもとでの均衡と同時手番は提供しない。 |
| 制度パラメータの根拠付け（[付録J](./appendix-j-grounding.md)） | RD-6.1，RD-1.5 | `cadl` 0.3.23から。静的な規則。αとβの指標とインセンティブの被覆率（`cadl norms-indices`）。戦略モデルにおける制裁の利得の項。0.3.24からは，SoSのすべての契約にわたる指標。規範によるα，β，λの形式的な意味は提供しない。 |
