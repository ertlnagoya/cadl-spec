# 10. 実装ロードマップ

CADLの実装と実用化に向けたロードマップを以下に示す。[第9章](./09-research.md)の研究方向性も考慮した計画である。期間は当初の計画であり，状況の列には公開中のリファレンス実装（`cadl` 0.3.8，2026年10月時点）が提供する範囲を記す。最新の状況は[`cadl`リポジトリ](https://github.com/ertlnagoya/cadl)のREADMEにある状況表を参照されたい。READMEの表はフェーズではなく機能を並べたものであり，2つの表の行は一対一には対応しない。

| **フェーズ**<br />（計画期間） | **目標** | **内容** | **状況** |
|---|---|---|---|
| Phase 1<br />（2026 Q2-Q3） | 言語コア設計・パーサ実装 | EBNF確定，パーサ実装，型検査器実装。MAPFシミュレータとの連携による初期評価。 | **実装済み。** パーサ，型検査器，シミュレータ向けIR・設定生成（Python，Unity，Go）を利用できる。 |
| Phase 2<br />（2026 Q3-Q4） | 検証エンジン（基本） | SMTベース無矛盾性検証，プロトコルデッドロック検出。ロボット配送シナリオでの検証実験。 | **実装済み。** Z3による無矛盾性検査とプロトコルのデッドロック検出を利用できる。検証手法`model_check`，`simulation`，`proof`は未対応である。 |
| Phase 3<br />（2027 Q1-Q2） | ランタイム・コード生成 | Python/TypeScriptランタイム生成，契約監視器実装。IoTデータ共有シナリオでの実証。 | **一部利用可能。** 契約監視クラスを含むPythonランタイムの生成を利用できる。TypeScriptの生成は計画段階である。 |
| Phase 4<br />（2027 Q2-Q3） | AI統合 | LLMによるNL→CADL変換，モード推薦エンジン。家庭内ルール設計シナリオでの評価。 | **一部利用可能。** LLMによるNL→CADL生成（構文解析・型検査・再試行のループ付き）を利用できる。モード推薦エンジンは計画段階である。 |
| Phase 5<br />（2027 Q3-Q4） | 制度遷移・モードマップ | 動的制度切替の安全性検証，モードマップ構築支援ツール。複数ドメインでの統合実験。 | **一部利用可能。** モード遷移のグラフ解析（到達可能性，行き止まり状態，閉路）と安全不変条件の充足可能性検査を利用できる。動的切替の安全性検証と構築支援ツールは計画段階である。 |
| Phase 6<br />（2028 Q1-） | IEC 62853連携・実用化 | アシュアランスケース連動，スマートコントラクト生成。実世界パイロットプロジェクト。 | **一部利用可能。** IEC 62853との対応付けレポートと，Solidity・OPA/Regoの生成を利用できる。アシュアランスケース連動とパイロットプロジェクトは計画段階である。 |

状況の列は処理系だけを対象とし，各フェーズに挙げた評価実験や実証は対象としない。なお，リファレンス実装は，当初の計画にないSoS-DSL拡張（[付録E](./appendix-e-sos-dsl.md)の`lifecycle:`と`monitors:`）とUnity C#の生成も提供している。
